## 1.1 当前架构

| 组件 | 选择 | 作用 |
| --- | --- | --- |
| bot 框架 | AstrBot v4.29.1 | 消息调度、模型接入、人设、插件、WebUI |
| QQ 协议端 | NapCat（OneBot v11 反向 WS） | 把 QQ 消息接入 AstrBot |
| B 站执行层 | bili-cli（`bili-agent`） | 登录、收件箱、看视频、评论、私信、投稿 |
| 共享记忆 | 自建 AstrBot 插件 `astrbot_plugin_fatfish_memory` | 人设、主人、事件、总结，QQ 与 B 站共用一个 SQLite |

插件源码在项目 `bots/`，通过 junction 挂到 AstrBot 的 `data/plugins/`，仓库与运行目录是同一份代码。

### 成长系统（参考 Hermes 与 dsh-bili-humanism）

| 层 | 内容 | 注入方式 |
| --- | --- | --- |
| L1 常驻 | 人设、主人资料、稳定偏好 | 每次对话 |
| L2 事件 | 消息、收件箱、看过的视频 | 按会话和权限检索；每日首次记录消息时按 retention_days 清理过期事件，默认 90 天 |
| L3 札记 | 主人用命令提炼 1～3 条「认识 / 下次怎么回」，带来源与日期 | 主人私聊中检索后注入 |
| L4 技能 | 稳定的应对方式与流程 | 命中场景时调用 |

原则：原始材料不直接变成指令；私人层只对主人开放；公开内容生成只读公开层。


## 1. 产品定位

一个以「大肥鱼」人格运营 B 站账号的自动化内容工具：给定话题，生成梗文案与分镜，合成带字幕和加速 BGM 的横屏视频，投稿到 B 站；同时通过 QQ 与主人聊天并保留私人记忆。

视频引擎独立于平台接入。AstrBot 只负责调度和交互，不重写合成逻辑。

## 4. 阶段 1：已完成基线

### 4.1 实现

- Python 标准库 + FFmpeg，无第三方运行依赖。
- 三模板：`single` 单人吐槽、`dialogue` 双人对话、`news` 角色搭配资讯截图。
- 输出 1920×1080、30fps、H.264 + AAC，封面、SRT、`result.json`。
- 字幕黄字黑边、自动换行、按帧对齐，单条最多 3 行。
- 音乐 0.5～2 倍速，随速升调或保调，音量、循环、淡入淡出。
- 场景轻微推近（zoom 0～0.10），字幕不随画面缩放。
- 本地 Web 拼贴页：98 个角色预览图、椭圆脸拼贴、画笔修补、音乐试听、导出 PNG/WAV/MP4。
- CLI：`doctor`、`validate`、`render`、`probe`、`serve`。
- 18 个自动化测试通过，覆盖真实编码、中文字幕像素、音轨、失败不产出。

### 4.2 文件约定

```
assets/originals/   用户原图，永不修改
assets/characters/  StarRailRes 角色库与 catalog.json
assets/music/       原创测试 BGM
examples/           三份模板配置
outputs/            成片、封面、SRT、报告
fatfish_video/      引擎、CLI、Web 服务
```

## 5. 阶段 2：AI 文案与分镜

### 5.1 输入

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `topic` | 是 | 话题或素材链接摘要 |
| `template` | 否 | 指定模板；不指定由模型选择 |
| `duration` | 否 | 目标总时长，默认 30 秒 |
| `characters` | 否 | 指定角色 ID 或名称；不指定由模型选择 |
| `tone` | 否 | 风格，默认「牢大式吐槽」 |
| `panel` | 否 | 资讯截图路径 |

### 5.2 输出

一份符合 `schema_version: 1` 的项目配置，外加生成元数据：

```json
{
  "schema_version": 1,
  "title": "标题",
  "template": "single",
  "assets": {"red": "../assets/originals/role-red.jpg"},
  "music": {"path": "../assets/music/demo-original.wav", "speed": 1.25, "volume": 0.65},
  "scenes": [
    {"duration": 10, "roles": ["red"], "caption": "第一段文案"}
  ],
  "output": "../outputs/topic.mp4"
}
```

元数据单独记录模型、提示词版本、耗时、校验结果，不写入项目配置。

### 5.3 规则

- 总时长与目标误差不超过 1 秒；单场景 3～15 秒。
- 每条字幕不超过 36 个汉字，超长由生成层拆分，不交给渲染层报错。
- 角色必须存在于 `catalog.json`；模板角色数量必须匹配。
- 文案不得包含私人记忆内容，只使用公开资料与给定话题。
- 模型返回非法 JSON 时重试一次；仍失败则明确报错，不产出半成品。
- 默认 `music.path` 指向项目内原创测试音轨；正式投稿前替换为有授权的音乐。

### 5.4 入口

```powershell
python -m fatfish_story create --topic "..." --duration 30 --out examples/ai-topic.json
python -m fatfish_video render examples/ai-topic.json
```

Python 入口：

```python
from fatfish_story import generate_project, StoryOptions
project = generate_project(StoryOptions(topic="...", duration=30))
```

- [x] mock 生成后的结构、角色引用和总时长通过校验
- [x] 非法模型输出被拒绝并给出可读错误
- [x] 离线 mock 模式完整跑通话题 → 配置 → 成片
- [x] 真实 DeepSeek 调用缺少配置时明确提示，不静默降级

## 6. 阶段 3：B 站观看与运营

### 6.1 能力

1. 视频理解：拉取公开视频信息、字幕、热评，生成结构化摘要。
2. 关注内容：按 UP 主或关键词订阅，手动读取每个来源最新五条，按播放量参考排序、合并来源并持久去重；不把播放量当作质量评分。
3. 评论回复：根据视频内容和人设生成回复草稿，默认人工确认后发送。
4. 投稿：上传成片、封面、标题、简介、标签、分区，查询审核状态。

### 6.2 接入方式

- 当前执行层为 bili-agent 0.6.0，登录凭据由它的独立配置目录管理，不写入项目或投稿元数据。
- 复用工具的本地限流和调用记录；不绕过验证码和风控，也不自动重试投稿。
- 所有写操作（评论、投稿）默认 `dry_run=true`，显式关闭才真正发送。

### 6.3 验收

- [ ] 公开视频信息与字幕的实际网络可用性
- [x] 认证和 CLI 错误明确失败，不自动重复投稿
- [x] 评论默认预览；投稿默认只生成本地草稿，不启动外部工具
- [x] 投稿前校验成片 `status: completed`、报告路径及视频/封面文件
- [x] 订阅、发现、来源合并、重启去重和来源失败通过临时库测试
- [ ] 实际投稿、账号分区与审核结果

发现命令和存储契约见 `docs/DISCOVERY.md`；投稿参数与确认步骤见 `docs/BILIBILI.md`。两者不会自动串联成无人确认的制作与发布任务。

## 7. 阶段 4：QQ 人格与私人记忆

## 8. 阶段 5：Updream 游戏二创

### 8.1 前置验证

- 确认账号可登录、可创建项目、可导出。
- 确认是否存在可用的网页接口；没有接口才考虑浏览器自动化。
- 确认平台条款允许生成内容的外部使用。

### 8.2 流程

项目配置 → `scripts/updream_handoff.py export` → 分镜、字幕时间与素材副本 → 账号持有人在 Updream 创建和生成 → 手动导出 → `verify-export` 完整解码检查。

交接包不会上传素材或确认授权，已有目录拒绝覆盖。导出验证只生成 `status: validated` 的本地媒体报告；它不是模板引擎成功报告，不能直接绕过现有投稿入口的输入限制。详情见 `docs/UPDREAM.md`。

### 8.3 风险

截至 2026-10-23，公开首页与登录入口可核实，但未找到可核实的官方公开 API 文档；不能据此断言没有 API。账号内创建、生成、导出、费用与素材外部使用范围尚未实测，不自动点击付费生成或推测账号内接口。

## 9. 阶段 6：整合与部署

- `deploy/compose.yaml` 组织 AstrBot 与 NapCat，bot 插件和素材分别挂载；视频、分镜和投稿入口保留独立 CLI / Python 契约。
- AstrBot、NapCat 镜像固定摘要；bili-agent 安装在独立环境中。构建上下文仅允许项目代码与打包配置，不带本机凭据、数据库或输出。
- `deploy/prepare.py` 默认只检查；`--write` 仅创建缺失状态目录和安全初始配置，不覆盖已有配置，不启动服务。
- 容器 WebUI 只映射服务器回环地址，OneBot 留在容器网络。初始配置关闭 B 站自动回复、收件箱轮询与真实写操作。
- 本机没有 Docker，已完成静态配置和文件准备测试；镜像构建、Linux 媒体、服务器账号登录、磁盘保留策略与正式运行仍需目标服务器验收。未增加无人确认的投稿队列或自动重试。

部署步骤及验收命令见 `deploy/README.md`。

## 10. 接口契约 v1

### 10.1 渲染

```python
render_project(project: Project | str | Path, output=None, *, overwrite=False, progress=None) -> RenderResult
```

- 成功返回视频、封面、SRT、报告、时长、帧数、分辨率、帧率、是否有音乐。
- 失败抛 `ProjectError` 或 `RenderError`，不返回成功对象。
- 默认拒绝覆盖；`overwrite=True` 才替换。

### 10.2 文案

```python
generate_project(options: StoryOptions) -> GeneratedProject
```

- `GeneratedProject.project` 为已校验的 `Project`，`.metadata` 记录模型与耗时。
- 失败抛 `StoryError`。

### 10.3 发布

```python
publish(video: Path, meta: PublishMeta, *, dry_run=True) -> PublishResult
```

- 只接收渲染成功的产物；渲染失败不会进入发布。
- `dry_run=True` 时只返回将提交的内容，不产生外部副作用。

### 10.4 版本策略

- 项目配置 `schema_version` 变更必须递增，旧版本保持可读或给出迁移提示。
- 契约变更写入 `docs/CHANGELOG.md`。

## 11. 素材与合规

- 用户原图只读，任何处理结果另存。
- 崩铁角色图、科比肖像、BGM 用于公开投稿存在版权与肖像风险，样片标注「测试用途」，正式发布前替换为有授权素材。
- 不把参考作者的视频直接当作成片素材。
- 音乐默认使用项目内原创合成音轨，不内置商业歌曲。

## 12. 风险与前置条件

| 风险 | 影响 | 应对 |
| --- | --- | --- |
| B 站账号没有投稿权限或触发风控 | 实际提交受阻 | 保留本地草稿，按平台提示由本人处理，不绕过校验 |
| Cookie 方案触发风控 | 账号受限 | 限速、只读优先、写操作人工确认 |
| QQ 协议风控 | 账号受限 | NapCat 独立账号、低频、避免群发 |
| 私人记忆串入公开内容 | 隐私泄露 | 同一库按权限和会话过滤，公开生成只读公开资料 |
| 素材版权 | 投稿下架或纠纷 | 正式素材授权，样片标注测试 |
| 磁盘增长 | 服务器不可用 | 输出保留策略与定期清理 |
| Updream 官方接口尚未核实 | 不能确认自动接入方式 | 先交付本地交接包，由账号本人验证官方功能和条款 |
