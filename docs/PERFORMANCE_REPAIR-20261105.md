# 内存与启动修复（2026-11-05）

本轮针对闲置模型占用、峰时回复等待和启动任务执行链。当前整机卡死的触发点尚未捕获，不能把以下优化当成蓝屏或所有卡顿的根因修复。

## 实测与取舍

- 00:18 左右，物理内存 31.62GB，可用 4.58GB，提交内存 36.98GB；非分页池 2.86GB、分页池 1.61GB。原神约 4.8GB 工作集，DSH 合计约 1.1GB，billion-context 子进程约 600MB。没有证据证明后者泄漏，保留其上下文功能。
- 闲置的 `qwen2.5:1.5b` 仍保留约 1.08GB 显存，过期时间到凌晨 2 点后。通过 Ollama 原生卸载请求成功释放，`/api/ps` 变为空；显存总占用从 5918MB 降至 4722MB。该差值包括同期其他进程变化，不能等同于释放物理内存。
- 后续一次采样可用内存 4447MB、CPU 14.2%、磁盘平均传输延迟约 1ms。此时没有重现资源耗尽；短采样不能排除之后的卡死。

## 修改

1. 复用 Ollama 原生空请求加载和 `keep_alive`，抽出小型共享请求客户端，不增加服务或依赖。移除模块导入时预热与 8 小时驻留；只有峰时确实需要回复时才后台加载，空闲保留改为 5 分钟。
2. 冷加载时立即走原有固定文案，保留原有拟人停顿；加载最多 45 秒，已加载后的本地生成最多 3.5 秒。不同群同时到达不排队挤占本地模型。超时或 HTTP 失败后可在后续请求重新加载，不缓存已失败的 Promise。峰时仍不转云端。
3. QQ 连接检查先行，本地模型服务检查移到启动末尾。非管理员转交已有最高权限任务时不重复检查模型。
4. 修复静默启动器：本机原 UTF-8 中文 VBS 在实际运行中未执行最后的启动调用。Unicode 对照执行成功，改用 ASCII 源文件避免编码问题。`scripts/run_hidden.vbs` 是可维护源，已部署到原任务共用的 `outputs/agent/run-hidden.vbs`，任务定义与触发器保持原状。
5. 启动器保持隐藏窗口，改为等待子脚本并返回真实退出码，避免包装器自身返回 0 被当成服务成功。微软说明中，`Run(..., False)` 会立即返回 0；参见 [Windows Script Host Run](https://learn.microsoft.com/en-us/previous-versions/d5fk67ky(v=vs.85))。
6. 启动脚本读取心跳时误用了 UTF-16，实际心跳是 UTF-8；仅修正该读取编码，保留脚本自身 UTF-16 与现有日志编码。
7. 并发项目更新已经将模型优化装入生产。核对源码、安装目录、归档包三个副本一致；补齐当时仍指向旧包的 `pnpm-lock.yaml`，核对 specifier、version 与 SHA-512 完整性一致，未重装依赖。
