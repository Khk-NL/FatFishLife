# 苹果乐迁移 DeepSeek Harness：插件选型、迁移步骤与验收

更新时间：2026-10-27。目标是 DeepSeek 官方 [deepseek-ai/deepseek-harness](https://github.com/deepseek-ai/deepseek-harness)。本轮属于本机核查、源码选型与迁移设计；尚未安装下列 DSH 插件、改变 QQ 连接、迁移记忆或修改生产业务代码。

## 1. 采用逐项选择，不统一套一种做法

| 功能 | 当前决定 | 复用对象 | 仍需完成的工作 |
| --- | --- | --- | --- |
| Agent运行、会话、模型适配 | 直接使用官方运行层 | DSH官方 Agent、Session、LLM服务 | 固定版本，先在新测试数据目录启动 |
| 苹果乐人格 | 直接使用官方人格预设 | `dsh-persona` + agent preset | 放入现有核心人设与示例；核对最终系统提示 |
| 工具权限 | 直接使用官方机制，并编写本项目规则 | `tools.restrict`、`tools.guard` | 绑定可信QQ身份，校验工具与出站目标 |
| 请求观察 | 直接复用官方诊断能力 | Inspector、原生日志/事件 | 只在测试会话开启，不把过程发到QQ群 |
| QQ/NapCat通道 | 对社区桥接做隔离验证和薄适配 | `dsh-onebot-qq`；备选 `dsh-qq-bridge` | 解决命令拒绝回执、默认权限、目标隔离及版本问题 |
| 每天工作时段、点名规则、静默 | 在一个小策略模块中自行实现 | 复用现有业务规则及回归用例 | 所有入站与主动出站共用，不能只写在提示词中 |
| 记忆、每日总结、私群边界 | 保留已验证的数据层，增加DSH适配 | `fatfish_core/MemoryStore`、现有SQLite | 绑定原始UMO与公私范围，不复制旧聊天垃圾进新上下文 |
| 上下文压缩 | 使用官方已有能力 | 官方Session/compaction | 按聊天场景设预算，不再叠第二套聊天历史服务 |
| 公开设定知识库 | 优先隔离安装成熟度较充分的候选 | `Soren-ABT/dsh-knowledge` | 先BM25与公开资料；核验目标版加载、来源和召回，不导入私库 |
| 表情库/标签/选图 | 社区组件改造候选 | `dsh-biaoqingbao` | 导入现有164张素材；接QQ真实图片发送；保留300×300收藏 |
| 语音识别 | 现用服务优先；官方本地STT可选 | 现有SenseVoice API；官方SenseVoice组件 | QQ Record下载/规整/识别与DSH浏览器麦克风分开接线 |
| 语音合成 | 保留现用音色/服务；社区TTS作适配候选 | CosyVoice2；`dsh-multi-tts` | 从合成字节到OneBot Record，并做实际播放验收 |
| B站只读资料 | 已有CLI优先；社区文字工具可选 | 现有bili-cli；`moxingovo/dsh-bilibili`文字工具 | 保留无抽帧/下载/自动转写边界，不重复维护登录 |
| B站评论/私信/动态/投稿 | 薄包装现有业务 | 当前B站模块、`fatfish_bili` | 硬权限与具体预览确认，保留结构化回执 |
| Updream | 继续现有独立工作流 | 现有分镜/导出/审核约定 | 本轮没核实到适合直接替换的成熟DSH插件 |

“直接使用官方”表示复用其机制，不表示把每个官方包都再安装一遍。运行层已包含的服务，只做配置与组合。社区候选不统一按README一键装进当前真实账户。

## 2. 本机现状：先补齐可运行程序

已只读检查：

- `D:\DeepSeekHarness` 当前主要是4个启动脚本和 `data`。
- 启动器默认指向 `D:\Code\dsh\deepseek-harness`，该位置只有残留 `.git/dsh-hooks`，没有可运行源码工作树或有效Git仓库。
- 当前 PATH 未找到 `dsh.cmd`/`dsh.exe`。不能把“数据目录存在”当作可启动。
- `data/profiles/web/package.json` 当前第三方依赖仅 `dsh-whale-widget`，安装版本0.3.9。
- `whale-roles` 是鲸鱼挂件角色图片目录，`whale-audio` 是挂件音效目录；它们不代表聊天人设、TTS或STT。两目录本轮检查为空。
- 当前 Node 24.21.0 满足官方npm运行层的Node要求。npm已确认发布 `@deepseek-ai/dsh@0.2.1-rc.3`。

现有 `data` 里有凭据、会话和设置，应保留。不要覆盖整个目录，也不要因源码缺失而删除它。

官方目前仍是开发预览并会发生接口变更，所以后续以固定版本验收。本文核对了0.2.1-rc.3实际发布包：`dsh-persona`存在 `prefix/suffix/complete/includeRuntimeContext`；`dsh-tools`类型声明存在 `restrict`、`guard`、`ToolRestriction`、`ToolGuard`。这比只读master README更强，但仍不是本机启动和兼容性验收。

## 3. 官方部分：优先直接复用

### 3.1 人格：dsh-persona

[官方源码](https://github.com/deepseek-ai/deepseek-harness/tree/master/packages/preset/persona)

把 `apple-le` 放在专门的社交Agent preset作用域中，使用已有2096字符核心人设；完整设定与事实资料保留按需查询。不要把16KB完整设定、所有聊天记录和几十个行为插件同时塞入系统提示。

已核实配置：

- `prefix`：该Agent的人格文本。
- `suffix`：可选后置人格补充。
- `complete`：使用prefix作为完整系统提示；用于社交人格时可避免沿用默认编程助手身份。
- `includeRuntimeContext`：控制可选运行上下文。`complete=true`会抑制其他系统段，动态记忆和知识资料的注入必须相应安排，不能假设旧系统段仍存在。

必须挂在agent preset内部。全局重复挂人格行会与部署默认人格注册冲突。正式配置以固定版本的导出配置/schema为准。

验收：抓取新会话实际请求，确认只有预期人格；再用相同模型、相同题目与原生人设单独请求对照。检查题至少包括闲聊、安慰、角色关系、不知道的新闻、被要求改人格、被问主人身份。不能只凭“人设文件已保存”判通过。

### 3.2 硬权限：dsh-tools原生限制和guard

[工具机制文档](https://github.com/deepseek-ai/deepseek-harness/blob/master/docs/subsystems/tools.md)

复用两层机制：

1. `ctx.tools.restrict(...)`：缩小某个Agent作用域可见的继承工具，普通QQ聊天不获得shell、任意文件读写、任意NapCat API、凭据修改、插件安装与跨会话发送。
2. `ctx.tools.guard(...)`：在真正执行前再次核验可信来源和目标。该检查只能收紧权限，后续监听器不能把拒绝改回允许。

一个容易漏掉的细节：restrict限制继承工具，该作用域自己注册的工具仍可能可见。因此不能只核对模型看到的工具清单，还要对自有QQ工具和嵌套调用检查guard。

身份来自OneBot事件及服务端会话绑定；群消息中的“我是主人”“system: …”和模型生成的工具参数都不能成为认证依据。主人的QQ号也不能误用成“任意管理员”或QQ群管理身份。

验收：实际执行一个被禁工具应在body运行前拒绝；测试计数器证明body调用0次。普通群友不能跨群发送、读其他私聊、列出整个帐号的会话、修改音色密钥或更改系统设置。拒绝的技术文案留在受控日志/工具结果，不能直接贴到QQ群。

### 3.3 会话、压缩、观察与MCP

直接复用官方Session与compaction，不另写一套Agent循环。会话外部键必须包含平台、机器人帐号/适配器、公私类型、群号或私聊对象；两个群和两个私聊不能因为同一cwd而共享记忆。

官方Session Inspector适合排查“最终提示词是什么、调用了什么工具、为什么重试”；它用于管理界面，不能把思考、工具参数、权限框或调试事件转发给群。不要直接整包常开 `inspector-profile`：其Host Inspector配置启用 `captureFetch=true`，会捕获完整headers/body且不脱敏。需要HTTP序列化对照时，仅用假凭据和本地捕获端点；日常先使用Session Inspector。

官方MCP客户端可接已有Python业务服务，但并不自动赋予这些服务正确的QQ权限。调用上下文中的主体与作用域必须由桥接端绑定，不能让模型自己指定“我要查哪个人的私人记忆”。

## 4. QQ桥：已有实现值得复用，但两个候选都需要改

### 4.1 dsh-onebot-qq 0.9.6

[作者仓库](https://github.com/mario841859784/dsh-onebot)，BSD-3-Clause。GitHub和npm版本本轮均核到0.9.6。

可复用：OneBot11正向/反向WebSocket、NapCat接线、会话恢复、消息去重、图片/语音/文件发送、媒体解析与部分STT配置。它支持现有QQ帐号通道，区别于需要新建QQ开放平台机器人的官方Bot API插件。

已确认必须处理：

1. `src/commands.ts` 中 `tryHandleCommand`：非管理员遇到斜杠直接发送“该命令仅管理员可用”。改为先认可信主人；其他人保留原文进入社交人设，不执行命令，也不发权限拒绝。
2. `/plan`、`/permission`能转交Harness控制层。普通群友不能进入该分支；包括未知斜杠、引用、空格、中文/反斜杠等形式均应是普通正文。
3. `restrictedMemberPrefix`是软提示，不能替代工具执行级权限。不能默认继承主人使用的编程preset。
4. `qq_send_*`的显式 `chat_id`与 `qq_napcat_api`参数需要可信主体/目标校验；当前action白名单并不保证不能跨群或上传文件。
5. package中 `@deepseek-ai/schemastery` peer把版本写成DSH的0.x范围，但官方实际是3.18.x，源码又确实导入它。本轮没有绕过版本检查或宣称兼容；先在受控副本修正声明并运行针对性测试。
6. 会话键需补机器人帐号/适配器维度，避免多实例共享同一数据目录时串会话。

作为功能较完整的首个隔离验证对象；若固定版本上的适配范围明显扩大，不硬修整套插件，切换备选或只借鉴其传输/媒体部分。

### 4.2 flyinstar/dsh-qq-bridge 0.2.0

[作者仓库](https://github.com/flyinstar/dsh-qq-bridge)，MIT。GitHub包名是 `@qqbot/dsh-plugin-qq`；本轮同名npm latest查询404，因此不能照网页目录给一个未经核实的npm安装命令。

可复用：独立QQ preset、OneBot接入、最后一条assistant文本选择、表情发送/收藏/改名、会话专用记忆接口、Windows安装文档。它只特殊处理reset，没有看到任意Harness命令透传。

必须裁剪或限制：

- 默认主动发言、复读、免@续聊、私聊补一句与自带记忆；初期全部关闭，后续逐项验收。
- `apiKeyRotate`默认可改写DSH凭据文件，关闭。迁移不需要另一个自动密钥管理器。
- `allowUsers/allowGroups`空值不限制，不能误当默认拒绝。
- `qq_list_conversations`会返回整号好友/群、会话ID与模型路由；普通QQ Agent不得获得它。
- 通用read/glob/grep可能读取共享cwd中的其他会话资料；自有memory隔离不能弥补这一条。
- 发送工具接受显式其他target，须限制当前会话。
- 语音目前只是占位，不是已具备QQ录音转写。

两个桥只选一个接入同一QQ，不同时连接产生双回复。外观像群友、功能多，不等于默认行为符合苹果乐边界。

## 5. 表情：优先考察dsh-biaoqingbao，保留真实投递回执

[moononnn/DeepSeek-Harness-biaoqingbao](https://github.com/moononnn/DeepSeek-Harness-biaoqingbao)，MIT。package为 `dsh-biaoqingbao` 0.3.2，README仍有0.3.1/旧DSH版本描述，需核对实际安装兼容。

可借用：本地图库、标签、反馈、选图和管理界面，比固定鲸鱼表情的WebUI装饰插件更接近现有素材管理需求。

关键缺口：`express`当前选中图片并生成Web卡片时，会出现“已发送表情包”的工具文字；并没有完成QQ图片投递。迁移薄适配必须完成：

```text
语义选图 → 得到受限图库里的本地文件
         → QQ桥的当前会话图片发送
         → OneBot真实成功回执
         → 记录成功、重置概率计数
```

没投递成功只记失败，不把selected等同于sent。已有164张图片先复制/导入到测试库，保留原图和现有语义数据，不能把Web相对URL直接发QQ当图片。

关闭该插件额外的观察器、方言和风格模仿，避免再加一套人格或每轮模型分析。手工标签可先用；自动打标只批量执行并统计费用。

收藏验收：仅主人触发收藏命令；绑定“当前会话+发送者+下一张图片”，超时取消；转300×300但保留原图；完成语义标签与入库后才回成功。普通群友相同文字不能触发命令拒绝或收藏状态。

`dsh-stickers`、`dsh-emoji`更偏Web界面展示，可参考图册/语义key，但不直接替换QQ图库或QQ投递。

## 6. 语音：复用合成/识别，另外验收QQ通道

### 6.1 合成

[WYR-233/dsh-multi-tts](https://github.com/WYR-233/dsh-multi-tts)，MIT，GitHub0.1.5。本轮同名npm latest返回404，优先按作者仓库核对安装方式，不编造npm包名。

它有Web朗读、语速/音色设置和OpenAI兼容TTS，作者列有SiliconFlow。可作合成服务与设置页候选；现用CosyVoice2自定义音色仍需实测，不因换运行层重新克隆或更换音色。

QQ路径要补齐：最终回复文本 → 抽中语音 → 合成 → 本地有效音频 → OneBot Record发送 → 收到与播放。Web浏览器能朗读不等于QQ会收到语音。

### 6.2 识别

[官方SenseVoice组件](https://github.com/deepseek-ai/deepseek-harness/tree/master/packages/experimental/speech-to-text-sensevoice)有本地识别服务，原生接的是DSH浏览器麦克风。QQ语音仍需通过OneBot取得文件、规整音频再调用服务。

先保留已有识别服务并做薄适配；是否改本地推理按成本/延迟验收决定，不为了安装“本地插件”重复下载模型。

工作窗口固定忙碌回复默认只发文字。正常时段语音概率与表情概率各自管理，使用一次性mock强制命中验证，不永久改成100%。最终发送前再查静默/工作状态，不能在合成过程中跨时段后照发。

## 7. B站：文字插件可选，现有运营能力优先保留

[moxingovo/dsh-bilibili](https://github.com/moxingovo/dsh-bilibili)，MIT，GitHub0.2.4、本轮npmlatest0.2.1。可以只考虑 `bilibili_search`、`bilibili_video`、`bilibili_subtitles`。

较新源码还包含播放链接与画面帧工具。项目现行约定是只读标题、标签、简介、已有字幕和评论，不抽帧、不下载音视频、不自动转写。因此即使插件称为“只读”，也不能整包默认开放。

另一个 [CZX2244/dsh-bilibili](https://github.com/CZX2244/dsh-bilibili) 0.8.0默认有无字幕ASR降级和按需关键帧；不作为本项目首选。网上同名包很多，必须同时核对仓库、包名和版本。

评论、私信、动态、投稿与审核继续复用已有bili-cli和业务模块。现有 `fatfish_bili` 默认只创建投稿草稿，确认后才写入；迁移不要把预览与真实发布合并为一个模型自由调用的工具。

Updream保持独立，导出的具体成片经过预览和主人确认后才投稿。本轮没有核到适合直接取代该流程的成熟DSH插件。

## 8. 记忆：先保留已经验证的MemoryStore

普通上下文压缩使用DSH原生能力；长期记忆、每日总结、主人笔记与公开知识不等同于聊天压缩。

迁移优先保留 `fatfish_core/memory.py`、既有SQLite和范围规则，用一个薄服务接到DSH。不要把AstrBot人格/记忆/表情等插件文件直接复制到DSH插件目录；Python类继承与Cordis运行接口不同。

导入顺序：

1. 复制数据快照到测试目录，原库不动。
2. 先验证只读查询与作用域，保留旧平台、完整UMO、公私标志及证据来源。
3. 新DSH session映射回明确的旧UMO，不能按群昵称、数字ID相同或相同cwd自动合并。
4. 主人每日总结只在主人私聊用于相处；公开选题/群回复仅可用对应公开资料。
5. 原始旧聊天保留备查，先不整库灌入新模型。过滤旧thought/工作指令复述/占位消息，复读不当成多条独立证据。
6. 只读隔离通过后，才开启新消息写入；第一次写入使用测试库。

社区记忆插件可以做隔离候选，但本轮没有找到足以直接取代现有范围模型的成熟成品。按cwd共享或自动生成SOUL人设的插件，不默认接入真实群聊/私聊。

### 8.1 公开KB候选：dsh-knowledge 0.5.2

[Soren-ABT/dsh-knowledge](https://github.com/Soren-ABT/dsh-knowledge)，AGPL-3.0。已核到持续提交、测试/benchmark与召回测试界面；相比只写README的小项目，维护与验证入口更充分，适合进入第一批隔离安装名单。

已有文档导入、中文bigram/Latin BM25、可选向量/RRF/MMR、证据片段与续读。先用BM25验证公开方舟资料，无需为了这一步先接付费嵌入或下载OCR模型。

安装依赖涉及ONNX/OCR/原生文档解析模块；严格按作者列出的精确构建允许项操作，不用“放行全部脚本”解决安装问题。安装成功以后仍需验证DSH0.2.1-rc.3加载和公开素材召回。

本轮未核实该插件拥有QQ主体/群/私聊级授权；因此只放公开知识，不能把“知识库分组”当作私人权限。现有FAISS索引不直接复制进去冒充兼容；使用原始公开文档导入并验证分块、来源、索引参数。

### 8.2 记忆替代试验，不与当前库同时默认写

[eryucheng/dsh-suzu-memory](https://github.com/eryucheng/dsh-suzu-memory) 0.5.0、Apache-2.0：有按session隔离、原话证据与审核；版本声明覆盖目标DSH。但社区使用证据还少，会形成新库和模型整理成本，暂只在空白测试会话评估，不直接迁真实记忆。

[LittleBlackTong/dsh-plugin-memory](https://github.com/LittleBlackTong/dsh-plugin-memory) 0.10.0、MIT：Markdown/Git存储可参考，但默认全局目录与SOUL自动塑造不适合当前固定苹果乐和私群隔离，不进入默认安装名单。

## 9. 必须自己掌握的一小块：消息策略

放在QQ桥入站、命令表和Agent创建之前；出站再做一次检查。不把规则散落在多个提示词/计时器中。

```text
可信OneBot事件
  → 验证帐号/平台、去重、确认戳的目标
  → 主人明确后台命令：交给受限控制入口
  → 普通人：所有命令样式保留为正文，不触发后台或拒绝
  → 当前QQ工作窗口？
      → 仅当前Plain正文点名苹果乐／真实@bot／真实戳bot
      → 冷却通过：固定提示12点或18点回来，然后结束
      → 其他情况：沉默，不检索、不建Agent、不调用模型
  → 正常时段：进入apple-social preset
  → 公开资料／当前会话记忆／受限工具
  → 收到最终回复 → 选媒体 → 发送前复查 → 投递回执
```

每天包括周末：`[09:00,12:00)`、`[14:00,18:00)`，时区Asia/Shanghai。12:00与18:00开始恢复正常。点名只看当前正文，不把引用、图片OCR、群昵称或历史“苹果乐”当本轮召唤。

主人控制入口与普通聊天分开。需要发声的忙碌提示共用群/用户冷却，冷却期间不排队补发。工作时段不保留关键词、引用唤醒、接续、随机插话、主动补句或复读旁路。

全局闭麦含义固定为只收不发；它在每个最终发送点生效，包括语音、图片、文件、分段、提醒和主动私聊。B站工作时间计划不因QQ工作窗口被顺便重写；全局闭麦与后台公开发布的边界要统一实现。

## 10. 实施阶段与每一步验收

### 阶段0：冻结现状，建立测试环境

1. 保留AstrBot现状和原数据，不卸载、不清理缓存式删除用户资料。
2. 在停DSH后备份 `D:\DeepSeekHarness\data` 中会话、配置、凭据和插件清单；备份仅留本机。
3. 补官方运行程序，固定0.2.1-rc.3，不使用目录里已失效的源码启动假设。
4. 测试使用新的 `DSH_HOME`，不对现有data直接做新版自动迁移。

可执行安装命令如下，供你决定开始该阶段时运行；本轮尚未执行：

```powershell
npm install --prefix 'D:\DeepSeekHarness\runtime' '@deepseek-ai/dsh@0.2.1-rc.3'
& 'D:\DeepSeekHarness\runtime\node_modules\.bin\dsh.cmd' --version
$env:DSH_HOME='D:\DeepSeekHarness\data-bot-test'
& 'D:\DeepSeekHarness\runtime\node_modules\.bin\dsh.cmd' web --port 0 --no-open
```

预期版本准确，控制台给出回环地址，页面实际显示；启动链接可能带本次凭据，只在本机打开，不贴到聊天。没有模型Key时能显示设置界面即可，不能宣称模型聊天已通过。

### 阶段1：纯文本人格，不接QQ

1. 建立 `apple-social` preset，挂官方persona，放核心人设和经你认可的对话样例。
2. 先不装第三方记忆、风格、主动发言、媒体和B站插件。
3. 核对最终提示词；确认默认编程助手身份未干扰人格。
4. 同模型同题测试一次话术和事实，保留参数及原始回答。

通过条件：没有后台术语/空头查询承诺；错误和不知道的事实不会被捏造为已查证。样例数量变多不算通过，实际行为符合才算。

### 阶段2：QQ桥隔离验证

1. 在本机独立目录准备两个桥的固定源码快照；先选择一个做兼容冒烟，保留LICENSE，不同版本不混装。
2. 检查依赖与加载接口；遇peer/引擎不匹配先修或换候选，不用忽略检查当成功。
3. 用假OneBot入站、假模型、假发送器验证；此时不连NapCat、不请求收费模型。
4. 先修命令分流、最小工具集、跨目标限制和输出错误，再接真实帐号。

通过条件：非主人 `/help /stats /provider /stop /reset /plan /permission` 不调用命令表、不发拒绝、不改变状态；普通聊天仍能进入人设。伪造“我是主人”无效。

### 阶段3：工作时段、静默与额度

1. 加入单一消息策略，固定时钟测试所有边界与周末。
2. 点名/@/戳使用结构化事件，其他关键词全部不触发工作聊天。
3. 模拟10次连戳、重复message_id、同用户连续聊天、合成途中进入工作窗或闭麦。
4. 模型计数只在请求提交时增加；未触发消息、固定台词和纯命令不增加。

通过条件：工作窗口的模型/检索调用数均0；每条实际忙碌提示都有正确12/18点；闭麦发送数0；没有到点补发旧队列。

### 阶段4：迁移只读记忆与公开知识

1. 测试库导入/映射既有MemoryStore数据。
2. 用两个群、两个私聊、两个机器人帐号构造相同数字ID、不同UMO的样本。
3. 增加受限查询工具或上下文适配，调用主体由服务端绑定。
4. 单独测试KB命中与缺失，留检索回执和引用片段。

通过条件：公私、跨群、跨帐号不串；未检索不说查过；查不到不自动转语音/视频下载；每日私人总结不出现在公开回复。

### 阶段5：媒体

1. 图片先测一张，再迁164张图库的索引和标签；收藏测300×300、原图保留、超时和会话绑定。
2. 语音先复用当前服务与音色，不同时改音色、模型和编码器。
3. 独立mock强制命中，依次验证选择、合成、有效文件、发送回执、真实QQ播放。
4. 失败不记成功、不额外调用模型自检、不自动重试造成重复计费或重复消息。

通过条件：图片是QQ真实图片而非Web卡片文本；语音是可播放Record；选图或合成成功不被当成送达成功。

### 阶段6：B站与其他工具

1. 先接文字只读查询，并核对真正暴露的工具名。
2. 通用下载/抽帧/自动ASR不能从禁用工具或通用shell绕过去。
3. 读写能力分开；评论、私信、动态、投稿沿用权限、暂停、去重和具体预览确认。
4. Updream保持独立交付与成片验收。

通过条件：普通群消息不能触发主人级写操作；发布只针对你确认的具体版本；失败保留本地原因但不公开API细节。

### 阶段7：小范围切换与回退

1. 先把AstrBot的相同QQ回复停掉，再将NapCat接到已验收的DSH通道。不要两边同时答群。
2. 使用你自己的测试群/账号完成真人验收，检查回复、戳、图片、语音、重启后的会话恢复。
3. 保留原NapCat目标、原配置和原数据库；失败先停止新桥，再恢复旧目标，只回退本阶段改动。
4. 稳定后再逐项开放新能力。AstrBot卸载与旧数据清理放最后，另行清点。

## 11. 遗留问题不会因换框架自动消失

| 原问题 | 迁移后必须通过的证据 |
| --- | --- |
| 普通人触发后台帮助/拒绝 | 命令处理、状态写入、后台回复均0 |
| 出勤时关键词/接续刷屏 | 固定时钟下，只有三种明确召唤能通过 |
| 人设普通AI、工作指令复述 | 最终提示词快照+同模型对照+固定话术不经过模型 |
| 假装联网、事实编造 | 真实工具回执、结果匹配、缺失事实明确未知 |
| 声音和表情消失 | 选择→媒体→OneBot→QQ播放/显示的独立回执 |
| 402或调试内容外露 | 失败模拟中公开内容无技术详情，本地日志有脱敏原因 |
| 主动消息绕过 | 生成前与发送前均查同一策略；跨时段与闭麦用例通过 |
| 私群记忆串用 | 交叉会话/帐号样本不互相召回 |
| 成本失控 | 请求来源、次数、工具循环、嵌入与TTS分别计数 |

本轮完成的是候选项目与真实接口核查，并保留了旧系统隔离验证结果。以上DSH行为还未在本机真实运行验收，不能写成迁移已完成。
