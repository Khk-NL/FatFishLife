# QQ 社交入口权限复核（2026-11-06）

本轮借鉴社区桥的权限分层，但未引入第二套桥或记忆引擎。检查发现四项具体边界问题，已在源码修正；不代表已经部署或完成真实 QQ 验收。安全回归使用合成记录、路径和账号，不发起真实平台请求。

## 1. 全库查询可绕过会话隔离

原社交工具守卫只检查名称和 `chat_id`，但记忆工具使用模型传入的 `scope/group_id`，未带认证会话。用临时数据库写入一条人工私有标记，当前 MCP `recall(scope="private")` 能返回该行；修改前从模拟群会话调用也被工具守卫放行。证据只记录命中行数，不记录真实内容。

相同边界覆盖 `recall/search/recent/candidates/stats/recall_all/remember`、通用知识库和 Obsidian 工具；`day_digest` 返回所有范围的内容片段，`style_terms` 扫描全库，日记读写也未隔离来源。空间列表可能含非公开动态，不能按普通公开网页处理。因此这些能力只保留给认证老大私聊。普通会话继续使用既有按会话记忆注入；公开 `lore_search/lore_context` 查询固定公开知识集合，Steam、网页与 B 站公开查询保持原权限。

没有重写 MCP 或靠模型承诺维持隔离。直接访问 MCP 的其他可信宿主入口保持原行为；这次修复的边界是 QQ 社交调用者。

## 2. 群内主人命令仍进入后台路由

原入口只验证主人 QQ，未限制私聊。以合成上下文调用现有命令函数：模拟群中的 `/model --default mock mock` 调用了默认模型保存方法，`/workspace` 会把合成工作目录发回群内。`/provider` 不在当前命令表，不能将其当作已经验证的命令。`/help` 本身只是帮助，但不能据此认为整条路由无管理能力。

策略入口与打包生成的 `tryHandleCommand` 现在同时要求认证主人及准确的 `private:<owner>` 会话。群消息即使来自主人也按普通聊天触发规则处理，不进入管理路由；主人的私聊管理保留。

## 3. 全局摘要混入普通会话提示词

旧 `socialChannelPrompt()` 无会话参数，直接读全局成长、峰时汇总、日记和运营结果；即使关闭查询工具，这些跨会话材料仍可能进入群或他人私聊。现默认只提供共享人格和渠道规则，仅从认证会话映射确认老大私聊后，才附加这些材料。未知会话不猜归属。原有按会话检索入口保持。

回归使用临时文件里的合成日记、峰时和任务标记，验证普通提示词不含标记、老大私聊能按原缓存周期读取和刷新；不靠“别透露”文字代替数据隔离。

## 4. 图片读取缺少本机目录边界

实际0.2.2-rc.1的 `read_image` 检查图片格式、大小和解码，但底层只读文件系统未限制可读目录。因此“只读”不能代表“只能读当前图片”；任意本机有效图片存在隐私风险，普通文本不会因此被当成图片读出。

社交守卫现同步解析文件与允许根的真实路径，仅允许桥原有媒体目录、显式图库；认证老大私聊另保留其工作目录。拒绝相对路径、file URL、根外路径、失效链接与未知会话；原生图片格式/大小/解码继续由原工具检查，没有另写图片读取器。guard在当前SDK中不等待Promise，因此不能直接套用异步媒体检查；目录语义沿用原桥媒体发送根。

临时路径测试覆盖正常媒体/图库、普通群和成员私聊的私有目录拒绝、老大工作目录、目录穿越、junction逃逸和缺失文件。只做路径检查，不读取真实图片或向模型发送图像。

当前媒体缓存根按账号共享，尚无逐图片的会话来源登记；本补丁堵住任意本机目录，不将其宣称为完整跨聊天图片隔离。后续若需要收紧，应沿用现有入站登记，而非新建第二套媒体服务。

## 验证与剩余范围

新增回归先在旧实现上失败，再验证修正：群/非主人私聊拒绝无边界存储工具、主人私聊仍可查询；公开查询保持；实际打包变换生成的命令方法在路由前拒绝群、伪造私聊目标和非主人发送者。测试不使用生产冻结标记；暂停行为仍由独立账号暂停测试覆盖。

仍不能把陌生网页内容当指令。此次没有证明网页工具存在认证或访问控制绕过，没有做账号登录、图片实际外发或公网访问测试。原本禁止命令执行、任意文件工具、插件安装、子代理和通用 OneBot API 的社交白名单继续生效。
