# 概率怎么调

都使用 `P = min(上限, p0 + n × 每次递增)`。`n`是该功能连续没成功发送的合格机会数；真正发送成功才回到0。语音、表情、关键词和主动聊天分别计数，完整群聊/私聊/适配器之间也独立。

本轮新增可调字段，**不替用户决定新数值**。保留现有基础值和启用范围；原来关闭的随机插话继续关闭。新加功能的递增默认0，表情沿用原先已经存在的递增值。

## 在控制台填哪里

AstrBot控制台进入“插件配置”，找到对应插件。保存后重载该插件或重启AstrBot，让固定读取的配置生效；重载会让进程内计数归零。

| 功能 | 插件及配置位置 | 基础概率 p0 | 每次递增 | 上限 | 单位 |
|---|---|---|---|---|---|
| 语音 | `tts_emotion_router` → `fatfish_policy` | `voice_probability` | `voice_probability_step` | `voice_probability_max` | 0～1，0.10=10% |
| 表情包 | `meme_manager` → `generation.emotion` | `probability` | `probability_step` | `probability_max` | 0～100，35=35% |
| 群随机主动插话 | `fatfish_offline` | `ambient_chance` | `ambient_probability_step` | `ambient_probability_max` | 0～1 |
| 关键词搭话 | `fatfish_offline` | `keyword_probability` | `keyword_probability_step` | `keyword_probability_max` | 0～1 |
| 私聊定时主动 | `proactive_chat` → `friend_settings.probability_settings` | `base` | `step` | `max` | 0～1 |
| 原有群定时主动 | `proactive_chat` → `group_settings.probability_settings` | `base` | `step` | `max` | 0～1；原开关不变 |

语音与表情使用社区插件原有流程；群插话沿用现有参与管理器，定时主动沿用社区已有调度器，不另开计时器。Proactive原有逐会话配置覆写同样支持 `probability_settings`，可为不同对话填不同参数；没有覆写时共享基础数值，但 `n`仍各自独立。

## 当前保留的值

- 语音：0.10 / 0 / 1，冷却180秒、最多80字，仍只允许“苹果乐乐乐”，节能时关闭。
- 表情：35 / 10 / 90（百分数），沿用已有35→45→55……90的设置。
- 群随机主动：本机现有基础值0、递增0，上限1，且 `ambient_hourly_limit=0`；继续关闭。要启用，除了填写非零基础或递增，还需把每小时上限设为正整数，原冷却为300秒；本轮不会自动开启。
- 关键词：1 / 0 / 1，保留原来命中关键词即尝试回复的行为，冷却90秒。
- 私聊定时主动：1 / 0 / 1，保留原有会话名单、时间间隔、未回复限制和原来启停状态。

斜线依次是基础/递增/上限。上限通常设为不低于基础，递增0就是固定概率。

## 例子

想要10%起，每错过一次多2个百分点，最多30%，语音/主动/关键词填 `0.10 / 0.02 / 0.30`；表情对应填 `10 / 2 / 30`。未发3次后下一次是16%，成功发送后回到10%。这里只举例，不会自动写入这些数值。

## 哪些会累计

- 语音：通过名单、会话、节能、长度、混合消息和冷却门禁后的一次回复机会；不中、合成失败或发送失败不清零。
- 表情：社区插件允许附图的一次真实回复，同一轮多个内部路径只计一次。抽中但没有可用图、没有附图或发送失败，不当成功。
- 群随机主动/关键词：满足各自条件的一条群消息；冷却、小时限额、无关媒体/转发等限制保持。@、引用、明确唤醒和已有续聊不由随机概率决定。
- 定时主动：满足既有白名单、免打扰、未回复上限等条件的一次定时机会，**不是收到一条消息就算一次**。未中走原重调度，不为判断概率调用模型。

离线/节能、暂停和权限门禁不会被递增绕过。修改概率也不扩大允许发言的会话范围。计数最多保留有限会话，不保存聊天正文和发送人；重启/重载后n归零。
