# QQ 冻结排查与暂停措施（2026-11-06）

## 当前结论

账号进入腾讯人工审核，具体命中规则仍未知。手机提示为“异常操作/涉嫌违规”，要求提交身份与用途材料。人工审核比上次增加了处理步骤，但仅凭界面不能判断处罚升级等级，也不能承诺解封。按手机 QQ 的正常“去处理”流程申诉，身份材料仅提交给腾讯，不放进项目或聊天。

已设置持久暂停标记 `data/.qq-account-paused`，没有自动到期。只有本人确认官方解封并授权恢复后才能解除；普通 `/resume`、任务调度、重启都不能自动解除。暂停期间不登录、不扫码、不发消息，也不进行复现封号测试。

## 已采取的措施

- 只停止已核实的机器人NapCat及其QQ子进程，其他QQ实例保留；空间桥通过原停止入口关闭。
- QQ策略入口、工具权限、最终发送、主动聊天、空间HTTP/MCP与向QQ交付的B站任务共用暂停标记；排队中的结果也在最终出口拒绝。独立B站任务保留原有开关，不因QQ故障一并关闭。
- watchdog默认仅维护DSH宿主。只有显式 `-AllowQQRecovery` 且没有暂停标记时才允许请求原QQ启动任务；一次请求不算登录成功。
- `start_all.ps1`、`start-napcat.cmd`及桌面对应启动器均在登录前检查暂停。空间启动器的启动/探活被阻止，`-Stop`仍可用。
- 空间计划任务保持禁用。启动计划任务因权限拒绝未能禁用，未绕过；其应用入口现由暂停标记阻止启动QQ。
- 既有开发自动任务已改为每5小时继续并检查状态，提示词保留冻结边界。额度未恢复不会绕过限制，也不自动恢复QQ。

## 复用方案审查

复核 [NoMindSama/qq-dsh-bridge固定版本](https://github.com/NoMindSama/qq-dsh-bridge/tree/5f3f4ffa70f444a612e8e02b740cd1dc1d6f663d)：会话分层、最终出口权限、幂等和闲时维护可借鉴，但仍是第三方客户端注入链，没有可验证的对照封号率。默认8次/分钟、60次/小时是项目选择，不是腾讯安全阈值。其readonly会话仍可能具有受文件策略约束的读取工具，不能照搬“普通人只有聊天所以绝对安全”的宣传。

其闲时compact复用原生能力，默认30分钟安静且约30万输入token；0.95仍保留安全阀，并非绝对永不在对话中压缩。selfNote为有长度和条数上限的自述，不保证记忆正确或人格成长。当前项目已有记忆、摘要及原生上下文工具，不并联第二套引擎或机械复制30万阈值。

[SnowLuma v2.4.0](https://github.com/SnowLuma/SnowLuma/releases/tag/v2.4.0)已核对反向OneBot与媒体接口。仅备好**全部禁用**的配置模板，以及复用原媒体缓存/大小限制/URL校验的语音base64薄适配；普通文件兼容仍待确认。没有下载安装、接受条款、注入QQ或真实账号收发。其[EULA](https://github.com/SnowLuma/SnowLuma/blob/v2.4.0/EULA.md)第5.4节要求自动部署专有组件预先取得书面授权，不能据本次开发授权代替。换组件不等于消除风控。

美国服务器直接登录QQ会改变账号环境；没有证据能量化它带来的风险，也不能承诺换IP可解封。当前不迁移登录点、不改VPN。后续若远程计算，可先评估保留熟悉设备的QQ登录点与远程DSH分离，仍须平台许可和账号恢复。

## 验证与剩余项

源码、模拟、原生隔离宿主、真实账号分别记录，最终验证数字和部署哈希见交接顶部。模拟使用虚构账号、回环OneBot和本地假模型；不请求真实QQ、B站或收费合成。
