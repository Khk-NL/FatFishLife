## 用户补充的报错

`DeepSeek Messages request failed (502/503)` 是接口请求的服务端/网关错误。已核对本机 SDK：它把 5xx 分类为 SERVER，并复用原生有限重试（默认最多 5 次，指数退避和抖动）。没有增加无限重试，也不自动重跑结果未知的工具调用。

官方将 503 定义为服务器繁忙：[DeepSeek 错误码](https://api-docs.deepseek.com/zh-cn/quick_start/error_codes/)。本次无凭据连通性检查中，直连和本机 7890 代理访问官方 Messages 模型列表均收到 401，说明这两条路径当时可达；没有调用模型，不能据此证明推理服务持续正常。当前状态页正常也不能否定此前的短暂失败。

“工具调用已记录、结果未持久保存”“进程在本轮完成前退出”与应用中途退出相符。既有巡逻狗日志有主动强制结束宿主的记录，但不能将所有历史中断都归为巡逻狗；蓝屏、人工退出也会产生此结果。本次修复消除了默认定时巡逻因单轮耗时而强杀宿主的路径。
