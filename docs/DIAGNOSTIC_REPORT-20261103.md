- **BugCheck（蓝屏）事件：2 条，错误码 `0x00000050`（PAGE_FAULT_IN_NONPAGED_AREA）**

- 小型转储文件：`C:\Windows\Minidump` 下 **5 个**；没有 `C:\Windows\MEMORY.DMP`。
- **WHEA 硬件错误事件：72 条**，其中绝大多数是 TPM：

**结论（有证据）**：这次不是"程序把系统关了"，而是**系统级异常重启**——先是页错误蓝屏（0x50），再叠加大量 TPM 硬件错误；`6008` 说明关机过程本身就没走完。属于操作系统/固件/硬件层，不是 DSH 或养鱼脚本发出的关机命令。

### 2.2 QQ 崩溃 0x80000003（现象 2）

- `STATUS_BREAKPOINT`，发生在 `QQ.exe` 内部（弹窗给出模块内偏移，形如 `0x00007FFD1BA66E3A`）。
- 环境：QQ `9.9.33-52230-aff854e8`（`D:\Q\QQ.exe`，腾讯数字签名有效，x64），NapCat **4.18.42**，`NapCatWinBootHook.dll` 同为 x64。
- `version_guard --check` 输出 `{"qq": "9.9.33-52230", "supported": true, "napcat_builds": 178}` —— **按版本号判断是"受支持"的**，所以这不是简单的版本不匹配。
- 直接启动 QQ（不注入 hook）能稳定跑；一旦经 `NapCatWinBootMain` 注入即崩。
- 现场：`Get-WinEvent` 里 **没有对应的 Application Error 记录**（屏幕有弹窗、事件日志没有），说明 QQ 是走到异常处理里自行弹框，没有走 WER 上报路径。

**结论（有证据）**：崩溃发生在 **NapCat 注入阶段**，不是 QQ 自身安装损坏；"版本在支持表里"与"注入实际稳定"是两件事。

### 2.3 巡逻狗自动启动失败（现象 4）

- 任务 `FatFishLife-Start`：`logonType=Interactive`、`runLevel=Highest`、`userId=kongb` —— **不需要 UAC 就能启动**，也不是 session 0 无桌面问题。

## 三、可能原因（按证据强度排序）

### A. 硬件/固件层不稳定（强证据）

`0x50 页错误` ×2 + `TPM 硬件无法执行命令` ×42 + 多次"关机未完成"。

常见成因：
1. **内存不稳**（XMP/EXPO 超频、接触不良、颗粒老化）——0x50 最典型的原因。
2. **TPM/固件（BIOS）版本问题**，或主板电池电量不足导致 TPM 状态异常。
3. **电源供电不足/瞬时功率保护**（本地模型跑在 GPU 上时功耗尖峰）——能解释"重负载时更容易发生"，但无法单独证明。
4. CPU/主板散热问题（需要温度日志，目前没有）。

> 与我的脚本无关：没有任何代码调用 `shutdown`/`Restart-Computer`；`6008` 明确写的是"关机是意外的"。

### B. NapCat 注入与 QQ 构建的兼容性（中证据）

版本号在支持表里，但注入即崩。可能是：
1. NapCat 4.18.42 的 `NapCatWinBootHook.dll` 对 `9.9.33-52230` 的偏移支持不完整（表里有 ≠ 实测通过）。
2. QQ 自动更新留下的半成品（`D:\Q\versions\9.9.33-52230-9.9.36-53644.zip`，95 MB，11-01 下载，未应用），运行时 DLL 与版本号不一致。
3. 反复强杀 QQ 之后残留的注入状态/共享内存段未清理。

### C. 自动启动环境差异（弱证据，缺日志）

1. 计划任务在登录后很早期运行，桌面/终端未就绪（`launcher.bat` 用了 `wt.exe`）。
2. 启动时 QQ 已有残留进程（半启动），`launcher.bat` 判重后直接跳过，导致"看起来失败"。
3. `start_all.ps1` 里 `Start-Process` 的参数在无控制台环境下行为不同。

### D. DSH 报错（未确认）

可能是插件面板 peer 缺失（rc.3 没有 `dsh-client-runtime` 等，已在文档记录）、Web 端 Cookie 累积（已加清理）、或页面重载时机。需要具体报错文本才能定级。
