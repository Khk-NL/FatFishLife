## 1. B 站：每天两次刷首页，给主人推荐视频并说明理由

| 项 | 值 |
|---|---|
| 时间 | `12:30`、`20:30`（每天） |
| 范围 | 首页推荐流，`--unseen` 只要没看过的 |
| 筛选 | 标题命中关键词才留：`明日方舟,游戏,音乐,能天使,苹果,科技` |
| 数量 | 最多 3 条 |
| 出口 | B 站私信发给主人（UID `297619957`），每条带一句推荐理由 |
| 去重 | bvid 记入 seen，并发过的不再发 |

实现：`fatfish_core/bili.py` 的 `feed_recommend()` + 上层筛选；旧实现在 `bots/astrbot_plugin_fatfish_bili/main.py` 的 `_auto_scroll`。

推荐理由要具体到"这条讲什么、为什么值得看"，不要写"看起来不错"。

## 4. 峰谷时段：本地 Qwen 与远程 DeepSeek 自动切换

**生效边界更正：**下面是旧运营文档快照。QQ忙碌门禁按用户要求**每天**09:00–12:00、14:00–18:00生效，包含周末；忙时固定话术不调用任何模型。价格峰谷/节假日是其他确需模型任务的独立成本策略，不能反过来放行QQ忙碌聊天。

| 项 | 值 |
|---|---|
| 高峰（贵） | 工作日 `09:00-12:00`、`14:00-18:00` |
| 低谷（便宜） | 其余时间，含周末与法定节假日 |
| 节假日 | `holiday_source=auto`，用 `chinese-calendar` 判断，含调休 |
| 高峰期行为 | 走本地 MiniCPM5-2B，不调 DeepSeek |
| 低峰期行为 | 正常走 DeepSeek |
| 本地模型 | **MiniCPM5-2B**（`llama-server`，端口 6193，别名 `fatfish-context`），端点与 key 路径见 `.env` 的 `FATFISH_LOCAL_LLM_*`；`--sleep-idle-seconds 60` 空闲自动卸载 |
| 备用本地 | Ollama `qwen2.5:1.5b`（11434）。实测中文理解弱（问"你是谁"回英文），只做兜底，不作为主力 |
| 限额 | 每小时 350 条后自动切本地 |

实现参考：`fatfish_core/logic.py`（窗口与节假日）、`bots/astrbot_plugin_fatfish_offline/local_model.py`（本地模型客户端）。

**这条在 DSH 里由谁执行**：DSH 的 `agent-default-model` 目前是单一 provider。峰谷切换要么写在策略层（每条请求前判断），要么用 DSH 的 provider 路由。迁移后先保留规则文本，等 QQ 桥通了再决定落地方式。

## 定时任务的落地进度（2026-10-29）

已拆成两层，避免把"几点做什么"和"谁去触发"混在一起：

1. **判断层**：`dsh/schedule.mjs`（纯函数）。`dueTasks(now, {lastRun})` 返回此刻该跑的任务，
   `nextRun(now)` 返回下一个。规则：到点才触发、宽限 60 分钟内补跑、同一天只跑一次、
   停机太久不补跑（避免重启后一次放出四件事）。12 项测试覆盖边界（提前/迟到/跨天/边缘）。
2. **执行层**：**未实现**。计划是在 `dsh/control` 里加一个 tick，调用 `dueTasks` 再走各业务；
   不另起第二套定时器，也不依赖系统 cron。

> 判断层可测，不代表定时真的会跑。在执行层落地并观察到真实触发之前，这张表不能写"已迁移"。
