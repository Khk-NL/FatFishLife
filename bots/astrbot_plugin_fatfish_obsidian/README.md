# 独立 Obsidian 知识库

使用 AstrBot 4.29 原生知识库与已配置的 Embedding Provider，将 `vault_path` 下的 Markdown 和文本笔记增量索引到 `FatFish-Obsidian-Private`。不修改源文件，不把此库加入全局 `kb_names`。源笔记会送到所选向量服务生成索引，请使用自己授权的服务。

每天默认北京时间 03:00 同步，每轮最多上传 25 篇新增或变更笔记；`pending` 表示还有笔记留待下一次同步，可修改 `max_files_per_sync`（上限 200）或手动继续。`.obsidian`、`.trash`、隐藏目录、符号链接和 Windows junction 不读取，单篇超过 1 MiB 会计入 `oversized`。文件哈希与索引 ID 存在共享数据库的独立运行状态中，笔记正文不进入聊天记忆和公开动态素材。

空文件和纯空白文件计入 `empty`，没有可索引内容时不调用向量服务、不计作上传失败，也不会伪造零向量。如果原先有内容的笔记被清空，会移除本插件对应的旧索引。`error_types` 只统计白名单阶段与异常类型（及直接原因类型），用于区别解析、分块、存储等失败；不包含异常原文、笔记名、路径或服务凭据。编码、接口限流等真实失败仍计入 `failed`，原版本保留并留待后续重试。

新版本完成原生解析、分块和向量上传后才删除旧索引；上传失败保留旧版本，下一轮继续处理。删除笔记时，仅移除本插件清单中对应的索引。断电后可按确定的文档名称恢复已成功的上传；不使用旧版同步插件的第三方脚本或零向量兜底。

设置 `owner_ids`（例如 `qq:主人账号`）或沿用共享记忆主人。只有主人私聊能使用 `/知识库 同步`、`/知识库 搜索 <问题>`、`/知识库` 和 `fatfish_private_knowledge` 工具。管理员身份本身不授予私人笔记权限；群聊调用直接拒绝，不执行检索。工具返回是私人参考材料，不能当成发布授权。

AstrBot 原生 `astr_kb_search` 只接受查询词，根据全局配置或当前会话的知识库选择进行检索，模型无法直接指定任意库。因此此库应同时保持在所有配置的 `kb_names` 和所有会话 `kb_config.kb_ids` 之外；部署时需要检查现有选择。Dashboard 管理员仍能看到原生库并改变这些选择，手动把私人库加入群会话会使原生检索在该群可用；插件不会拦截或撤销管理员之后的这类配置。

同步和检索的实际结果通过 `record_capability` 接入私人能力经历、每日反思和 `/生活 成长`，只记录固定标签与阶段，不记录笔记、路径、查询或错误原文。模型可在私人日记里总结学到了什么、下次如何改进；自动公开动态仍只使用原有公开经历。
