# astrbot_plugin_fatfish_offline

配置时段内不调用任何云端大模型，改用本地规则回复。人设和角色卡不受影响。

## 工作方式

1. 每条消息先经过本插件。非离线时段的普通消息直接放行；空 @ 和戳一戳始终先由本地规则处理。
2. 离线时段：`event.stop_event()` 在网络请求前拦截，普通聊天不会产生任何 API 调用。
3. 被 @、点名、私聊或连续追问时，按意图从台词库挑一句回复；无人叫它时保持沉默。
4. 恢复时间由配置动态计算，台词里只有 `{resume}` 占位符。
5. 状态写入 `data/plugin_data/astrbot_plugin_fatfish_offline/offline.json`，B 站自动回复插件会读取它，离线时同样不发模型请求。

戳头像使用 NapCat 的原始 `notify/poke` 或 `Poke` 组件识别目标，只响应戳到机器人本人的事件，在线和离线均用本地戳一戳台词。只发一个空 @ 会得到另一组简短本地回应；@ 加文字或图片继续普通对话，不会当成戳一戳。群聊和私聊均适用。

## 配置

| 项 | 说明 |
| --- | --- |
| `enabled` | 离线模式开关 |
| `windows` | 时段，默认 `09:00-12:00`、`14:00-18:00` |
| `weekdays` | 工作日，默认周一到周五 |
| `holidays` | 法定节假日例外（YYYY-MM-DD） |
| `workdays` | 调休补班（YYYY-MM-DD） |
| `reason` | 离线原因，决定台词库 |
| `group_cooldown` / `user_cooldown` / `max_per_hour` | 节流 |
| `context_ttl` | 短期上下文有效期 |
| `owner_qq` | 主人 QQ，可用命令切换模式 |
| `daily_apple_pie_group_id` | 每日口令目标群号，默认留空停用 |
| `daily_apple_pie_platform_id` | QQ 连接 ID，默认 `napcat` |

## 每日啊噗噜派

在 AstrBot 控制台的插件配置中填入 `daily_apple_pie_group_id`，保存并重载插件后启用；清空群号后保存、重载即可停用。`daily_apple_pie_platform_id` 通常保留 `napcat`，只有修改过 AstrBot 平台 ID 才需要同步修改。

每天按北京时间抽签，周末照常，与离线时段无关，也不调用模型：

| 时间 | 当轮概率 |
| --- | --- |
| 18:01 | 25% |
| 19:01 | 50% |
| 20:01 | 75% |
| 21:01 起 | 100% |

若此前尚未中签，每小时按当轮概率抽一次；中签后只向配置的群发固定一句“啊噗噜派！”。每日最多尝试发送一次，换群或重载不会重置当天记录。未中签的时段也会落盘，重启不会在同一时段重抽。

服务重启只处理当前时段一次，不补跑错过的轮次；跨日恢复新一轮。发送前先保存当天记录，发送异常、结果未确认或中途取消时不自动重发，避免重复消息。平台尚未就绪时等待连接，不消耗抽签。

## 命令

```
/离线 状态
/离线 开
/离线 关
/离线 自动
```

`开/关` 是手动覆盖，优先级高于时段判断；`自动` 清除覆盖。

## 台词

空 @ 和戳一戳分开本地应答，使用带一点嘴硬和装傻的苹果乐短句，在线也不为这两类空事件请求模型。@ 后有正文或附件则继续处理内容。工作时段为工作日 09:00～12:00、14:00～18:00，对外说自己在企鹅物流上班、忙着送件，按实际恢复时间约定下次聊天。

`templates.py` 按原因和意图分组，支持 `{name}`、`{resume}`，带近期去重。改台词不需要动逻辑。

## 测试

```powershell
python -m unittest discover -s tests -p "test_offline*.py" -v
python -m unittest discover -s tests -p "test_daily_apple_pie.py" -v
```

覆盖时段边界、周末/节假日/调休、恢复时间文案、意图识别、节流和上下文过期，以及每日口令的概率边界、持久去重、跨日、时区、发送失败和任务取消。插件发送测试使用模拟对象，不向真实 QQ 发消息。
