# astrbot_plugin_fatfish_bili

用 bili-cli 驱动 B 站账号，和 QQ 共享记忆。

## 依赖

```powershell
python -m venv D:/Code/Apps/bili-venv
D:/Code/Apps/bili-venv/Scripts/pip install bili-agent
```

插件配置 `bili_exe` 指向 `bili.exe`，`bili_home` 指向独立配置目录（登录、限流、审计都留在这里）。

## 登录

```
/bili 登录
/bili 确认
```

二维码默认 180 秒有效。登录成功后把 `owner_uid` 设为主人 UID。

## 命令

```
/bili 状态
/bili 收件箱
/bili 看 BV1xx411c7mD
/bili 搜 关键词
/bili 推荐 5 1
/bili 点赞 <BV号>
/bili 取消点赞 <BV号>
/bili 收藏 <BV号> [收藏夹ID或名称]
/bili 取消收藏 <BV号> [收藏夹ID或名称]
/bili 动态 [UID]
/bili 动态详情 <动态ID>
/bili 发动态 <正文>
/bili 回复 <BV号> <评论ID> <内容>
/bili 私信 <UID|owner> <内容>
/bili 记忆 <关键词>
```

`dry_run_writes` 默认 `true`：评论、私信、点赞、收藏、动态发布只返回预览，不真正执行。取消收藏未指定收藏夹时，会从账号的所有收藏夹移除该视频。动态发布没有自动重试；若回执不确定，先用 `/bili 动态` 核实。

登录、确认、状态、收件箱、立即处理消息和发送私信，仅限主人或 AstrBot 管理员在私聊中使用。QQ 主人身份同时校验平台和 `owner_qq`，其他平台的同号用户不会获得权限。公开视频查看、搜索和公开记忆检索继续可用。

首页推荐是当前账号的个性化结果，推荐、动态查询及新写操作也仅限主人或管理员私聊。推荐默认 5 条，最多 30 条，支持页码，过滤 bili-cli 本地看过的视频。模型可用 `bili_recommend` 读取同样的推荐；写操作由明确的 `/bili` 命令触发。

`/bili 看` 与 `bili_watch` 共用纯文字读取逻辑：标题、标签、简介、平台提供的文字总结、已有字幕和热评。直接复用 bili-cli 的 `video watch --frames 0 --transcript subtitle`，不下载音视频、不抽帧、不调用转写模型；没有字幕时仅使用其余文字。不会发送旧的抽帧图片或建议自动转写，也不使用 `--record` 向 B 站上报观看历史。记录中的“读取文字资料”不代表看完视频。

标签学习复用同一读取函数，每个选中视频只调用一次 CLI，记录带来源的文字摘录；评论表达提取使用已有本地规则，不额外调用模型。凭据管理、限流与 B 站数据访问继续交给 bili-cli，本插件只连接 AstrBot 的权限、定时和成长记录。

`/bili 发动态` 发送纯文字，正文中的 `@` 转为全角，避免意外提及其他用户。预览及未确认的发送不写为已发布记忆；只有有效动态 ID 回执才记为发布成功。

## 记忆

写入 `astrbot_plugin_fatfish_memory` 的同一个 SQLite：

- 读取的公开视频文字资料、公开评论回复：`public`
- 收件箱（包含私信和系统通知）、私信：`private`

`/bili 记忆` 在群聊或非主人会话中只检索公开记录；私人记录仅向主人或管理员的私聊开放。LLM 的 `bili_inbox` 工具遵循同样的权限检查。共享记忆插件重新加载时，会把旧版错误标成公开的 B 站收件箱记录转回私人层；B 站查询也会排除这些旧收件箱记录的公开访问。

后台通知可以保留公开评论回复，但只报告私信已处理，不附带私信正文或回复内容；完整结果通过主人私聊中的 `/bili 处理` 查看。

自动回复会从同一份共享记忆库读取相关笔记：公开评论始终只读公开层，即使评论来自主人；只有 `owner_uid` 本人的私信可读取私人笔记与札记。评论原始对话按视频隔离，私信按 UID 隔离，QQ 原始聊天不会自动串入 B 站。成功发送的来信与回复保留会话标记，预览不会记录成已发送的对话。

`inject_context` 默认开启，`max_context_chars` 默认 1800。共享的持久化与检索来自项目的 `fatfish_core` 包；安装项目后可单独加载本插件，不再从相邻记忆插件导入实现。现有 `reply_persona` 保留，检索资料作为附加背景。

记忆库路径按 `FATFISH_MEMORY_DB`、本插件 `memory_db`、记忆插件配置、旧默认路径依次解析。回复去重和离线信号也使用同一 SQLite，旧 `seen.json`／`offline.json` 只首次导入并保留用于回退；重载不会重新回放旧记录。

`enable_inbox_poll` 默认关闭。开启后每 `poll_interval_seconds` 秒分别读取 @、评论回复和未读私信，会消耗 B 站未读状态。

## 注意

- bili-cli 自带评论 10 秒/次、私信 10 秒/次等本地限流，遇到风控会直接报错，不重试。
- 视频投稿在阶段 1 完成后接入，这里暂不提供 `/bili 投稿`。
